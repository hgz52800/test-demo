# 海心 AI GEO 智能增长系统：阶段一设计规格

- 日期：2026-09-25
- 仓库：`hgz52800/test-demo`
- 分支：`feature/haixin-geo-saas`
- 范围：产品基础与 GEO 总驾驶舱
- 状态：待用户审阅

## 1. 产品目标

将当前 Python 入门示例仓库逐步转为海心 AI 的 Web SaaS 产品。阶段一交付一个可在浏览器访问、视觉上遵循 Stitch 设计、交互可演示的基础工作台和 GEO 总驾驶舱，为后续真实检测、优化闭环和商业化能力提供清晰边界。

产品面向企业品牌团队、营销服务商和 GEO 服务商。用户打开工作台后，应能快速看懂当前品牌表现、趋势和优先增长机会，并能进入对应的后续模块。

## 2. 已确认的输入和约束

- 用户确认以 `hgz52800/test-demo` 为开发仓库。
- 用户提供的 `stitch_ai_geo.zip` 是视觉和页面结构参考，包含驾驶舱、竞品分析、Prompt 详情、平台接入、知识内容、信源地图、优化任务、回答侦测、内容工厂、报告等页面样稿。
- `haixin_geo_growth_system/DESIGN.md` 提供了颜色、字体、布局、间距、组件和响应式规则。界面实现应优先复用这些设计语义，并根据各屏 Stitch 截图落实实际页面比例与层级。
- 当前仓库仅有 Python 入门示例和既有文档，没有现成 Web 技术栈。产品前端将采用 Next.js、React 和 TypeScript。
- 第一阶段采用真实感 Mock 数据演示。页面不应声称已连接 DeepSeek、豆包等平台，也不应声称推断这些平台的内部算法。
- 所有诊断文案应将结论限定为可观测的 AI 回答、引用来源和公开信息。
- 不使用真实 API 密钥或生产用户数据，不连接第三方发布渠道。

## 3. 阶段一用户流程

1. 用户访问产品介绍页，选择进入工作台。
2. 用户进入演示登录入口并打开预置的海心家居品牌工作区。
3. 用户在工作台顶部查看或切换演示企业/品牌项目、查看通知和帮助入口。
4. 用户从左侧导航进入 GEO 总驾驶舱，按 7 天、30 天、90 天或自定义时间范围查看核心指标。
5. 用户查看趋势、平台分布、监测覆盖和待办任务。
6. 用户在“AI 今日发现的 GEO 增长机会”列表中查看问题、平台、当前表现、竞品表现、可观测依据、影响程度、优先级和建议动作。
7. 用户点击机会的详情或“生成优化方案”入口，看到明确标记为演示数据/模拟生成的方案预览；可创建演示任务并得到成功反馈。
8. 用户从导航进入尚未在本阶段实现的模块时，看到有内容的模块介绍和明确的演示状态，不进入空白页或死链。

阶段一的演示登录不收集、不保存真实密码。真实身份验证和多租户访问控制放在后续 SaaS 基础阶段。

## 4. 范围

### 本阶段交付

- 产品介绍页和演示工作台入口。
- 登录/进入演示工作区页面，不实现真实身份验证。

  - GEO 综合指数、曝光率、提及率、推荐率、引用率、覆盖问题数量、监测问题数量、平台数量、环比和任务完成率。
  - 7/30/90 天及自定义时间筛选。
  - 趋势图和 AI 平台表现。
  - 今日增长机会列表。
  - 最近优化任务及完成情况。
- 机会详情面板、模拟优化方案预览、创建演示任务和完成状态反馈。
- 主要导航项目和响应式状态；未交付模块使用可理解的阶段介绍页，不伪装成已有能力。
- 统一设计令牌与基础组件：Button、Input、Select、Card、Badge、Tabs、Modal/Drawer、Table/列表、Toast、Skeleton、Empty、Error。
- 独立的 Mock 数据与服务适配层，数据类型与未来真实 API 边界。
- README 本地运行说明和无秘密信息的 `.env.example`。

### 不包含

- 真实 AI 平台请求、爬虫、浏览器自动化、模型内部算法分析。
- 真实身份验证、企业成员管理、角色授权和生产级多租户隔离。
- 真实数据库持久化、真实任务调度、自动复测、实际报告导出。
- 对第三方网站发布内容，或未经用户确认的外部写操作。
- 生产部署、真实 API 密钥、付费服务或生产环境数据。
- 阶段二至四的完整功能实现。

## 6. 设计与响应式规则

- 以 Stitch 导出页面和截图为视觉基准，不自行替换其品牌视觉。
- 使用 `DESIGN.md` 中的颜色、字体、圆角、阴影、间距和中性色规范；在实际页面中优先还原截图中的导航、卡片、图表、数据模块和层级。
- 中文字体优先使用系统中文字体栈，Inter 和 JetBrains Mono 作为拉丁文字与数字字体的优先项；外部字体不可用时仍要可读。
- 桌面（>=1280px）：完整侧边导航和多列数据布局，内容宽度保持可读。
- 平板（768-1279px）：导航折叠为图标栏，卡片重排。
- 手机（<768px）：单列信息流、可触达的移动导航；表格改为摘要卡片或横向滚动，不挤压正文。
- 颜色对比、焦点可见性、键盘操作、语义化按钮和表单标签应满足基本可访问性。
- 图表需包含文本标签或摘要，避免只依赖颜色传达数值。

## 7. 前端结构与模块边界

拟采用 Next.js App Router、React、TypeScript 和 CSS 设计令牌。页面负责组合组件，不直接持有业务 Mock 常量。

建议模块边界：

- `app/(marketing)`：公共介绍页与演示入口。
- `app/app`：工作台路由、导航和布局。
- `components/ui`：通用交互和状态组件。
- `components/dashboard`：指标、趋势、平台表现、机会和任务组件。
- `features/opportunities`：机会详情和方案预览流程。
- `lib/domain`：品牌、指标、问题、机会和任务类型。
- `lib/services`：平台与业务适配器接口。
- `lib/mock`：演示数据和 Mock adapter 实现。
- `lib/state`：仅存工作台交互所需的轻量状态；不存秘密或真实凭据。

不为尚不存在的需求引入大型通用框架。服务接口应足以将 Mock 实现替换为服务端 API。

## 8. 服务接口与数据流

阶段一提供以下边界，接口命名可在实现计划中细化：

- `DashboardService`：按品牌和时间范围获取仪表盘指标、趋势与任务汇总。
- `OpportunityService`：获取机会列表和详情。
- `OptimizationService`：生成演示方案、创建演示任务。
- `WorkspaceService`：获取可选演示组织和品牌项目。
- `AIPlatformAdapter`：定义可扩展平台标识和展示元数据；当前只提供演示平台记录，不声称真实接入。

数据流为页面 → 服务接口 → Mock adapter → 有类型约束的 fixture。后续接入真实系统时，服务端实现负责鉴权、输入验证、配额检查和上游调用，前端不接触密钥。

## 9. 阶段一领域数据模型

不在本阶段接入数据库，但定义能映射到未来数据库的 TypeScript 类型：

- `Organization`、`Workspace`、`BrandProject`：演示组织、工作区和品牌项目。
- `AIPlatform`：平台标识、显示名称和可用性状态。
- `DashboardMetric`、`MetricSeriesPoint`：指标值、单位、变化值、时间点。
- `Question`、`Competitor`：监测问题、品牌和竞品引用。
- `GeoCheckSummary`、`AIAnswerSummary`、`CitationSummary`：可观测检测、回答和引用摘要。
- `OptimizationOpportunity`：问题、平台、证据摘要、竞品表现、可能原因、影响、优先级、建议动作、难度和状态。
- `OptimizationTask`：名称、问题、平台、类型、优先级、状态、创建时间和计划复测时间。
- `UsageSummary`：演示套餐名称及已用/总量摘要；注明模拟数据。

机会分析文案必须能指向对应回答/引用的演示证据，并使用“可能原因”“公开可观测信息”等措辞；不能断言模型的隐藏机制。

## 10. 页面状态与失败处理

- Loading：驾驶舱模块显示骨架屏，避免整个页面空白。
- Empty：没有检测记录时展示“还没有 GEO 检测数据”及启动演示检测的按钮。
- Error：服务失败时显示局部错误说明、重试按钮和不丢失导航的页面框架。
- Success：创建演示任务后显示任务编号/名称和状态反馈。
- Demo 标识：关键模拟数据与模拟生成结果均能被用户识别为演示内容。
- 筛选：时间范围改变后，趋势与汇总值同步更新；自定义时间需校验起止顺序。
- 所有可见按钮都应导航或触发可见反馈；未实现能力不显示可误解的操作按钮。

## 11. 安全、隐私与可扩展性

- 不在客户端打包密钥、数据库密码或服务端环境变量。
- 提供仅含键名和说明的 `.env.example`。
- 演示表单不收集真实密码或个人敏感信息。
- Mock adapter 与未来真实服务实现隔离；平台 ID 使用稳定字符串，不依赖固定的平台清单。
- 真实 API 接入须由服务端代理，并在服务端集中处理输入校验、鉴权、配额、超时、错误映射和日志脱敏。
- 本阶段的模拟数据不得对外宣称为真实监测结果。

## 12. 验收标准

1. 项目按 README 指引可安装并启动，浏览器能打开公共入口和工作台。
2. 工作台在 1440px 桌面、常见笔记本/平板尺寸和窄屏手机尺寸下无横向溢出或阻断内容。
3. 驾驶舱能显示有来源标记的 Mock 指标、趋势、平台表现、机会和任务。
4. 时间筛选、项目切换、导航、通知/菜单、机会详情、方案预览、演示任务创建都有可见且一致的交互反馈。
5. 主要导航链接无死链；未交付模块清楚标记为预览阶段。
6. 页面样式对照 Stitch 截图与设计令牌，保留标志、层级、色彩和密度特征。
7. 服务 Mock 不嵌入页面组件；业务类型及未来 API 接入边界可辨认。
8. `.env.example` 不含真实密钥，客户端资源不含密钥或密码。
9. README 说明当前为 Mock 演示、运行方法和未来真实接入的配置位置。
10. 完成后检查首页与驾驶舱交互、不同视口布局、构建/类型检查及浏览器严重错误；如项目没有现成测试，则不凭空宣称测试通过。
